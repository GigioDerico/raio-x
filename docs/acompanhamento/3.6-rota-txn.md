# 3.6 — Erros de uso nas rotas de lançamento (correção avulsa)

Início: 2026-10-02 · Estado: concluída em 2026-10-02 (aprovada pelo dono, integrada à `main`)
Origem: revisão da 3.4 (pendência registrada em `3.4-ajustes.md`)

## Objetivo
`PATCH`/`DELETE /api/txn/[id]` e `PATCH /api/txn/bulk` respondem 400/404 a erro
do usuário em vez de 500/503: JSON inválido, corpo que não é objeto e id que
não é uuid.

## Checklist
- [x] `corpoJson` dentro do `comUsuario` nas duas rotas
- [x] Corpo que não é objeto tratado como vazio
- [x] Id que não é uuid → mesmo 404 de id alheio (`[id]`); ids que não são uuid descartados (`bulk`)
- [x] Data que passa no formato mas não existe ("2026-13-45") → 400
- [x] typecheck, test e build passando
- [x] commit e integração (dono conferiu Lançamentos e aprovou)

## Feito
- 2026-10-02 — Branch `correcao-rota-txn`; as quatro correções em `src/app/api/txn/[id]/route.ts` e `src/app/api/txn/bulk/route.ts`.

## Decisões
- Mesmo padrão de `/api/ajustes` e `/api/accounts/[id]` (fatia 3.4): `corpoJson`
  dentro do `comUsuario` e `ehUuid` antes de ir ao banco.
- Data inexistente entrou junto: mesma classe de erro (do usuário, virava 503).
- No lote, id que não é uuid é descartado em silêncio: não pode ser de ninguém,
  e um lote com só ids inválidos cai no "nenhum lançamento selecionado".
