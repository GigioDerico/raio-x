# Fatia 3.2 — Categorias Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar `/categorias` com as 13 categorias, valores, barras, comparação histórica e links para os lançamentos no mesmo recorte.

**Architecture:** Uma função pura monta o modelo da tela usando as contas já portadas na 3.1. A página autenticada carrega o contexto pelo repositório existente e renderiza um componente servidor com as classes do ranking do painel. Nenhuma consulta SQL, migração, API ou dependência nova é necessária.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, CSS existente; testes sem framework em `scripts/testes.ts`.

**Spec:** `docs/superpowers/specs/2026-09-30-fatia-3-design.md`, §§2, 4, 5 (Categorias e filtro global), 7 e 9. Contexto: `docs/acompanhamento/fatia-3.md`; visual: `docs/design-system.md` e ranking de `src/app/(app)/page.tsx`.

## Global Constraints

- “Nenhuma chamada de IA dispara por navegação.”
- “Toda tela nasce com: primeiro uso, vazio por filtro, carregando (esqueleto), erro que diz o que falhou.”
- “Cada subfatia fecha com `npm run typecheck && npm test && npm run build` e um commit.”
- “`user_id` sempre de `exigirUsuario()`; posse sempre no `where`, inclusive nos joins do adaptador.”
- “Nada chega ao cliente além do que a tela mostra.”
- “Clique abre `/lancamentos?cat=…` mantendo o filtro.”
- Portar as regras existentes; não alterar `baseCategoria`, `severidade`, `mesAtual`, pagamentos ou estornos. Contexto já vem filtrado por cartão e obra, com todos os meses históricos.
- Manter os nomes de `CATS`, português no código e commits, nenhuma variável `NEXT_PUBLIC_`, nenhuma dependência nova. Celular em 390px e temas claro/escuro.

## Review Focus

1. Histórico curto ou com lacunas: usar até três meses anteriores **disponíveis**, contando categoria ausente como zero; não comparar com meses posteriores.
2. Total zerado/negativo e estornos: manter valores assinados; barras finitas de 0–100%, sem representar zero ou crédito como gasto positivo.
3. Cartão com mês mais recente diferente do global: link fixa o mês efetivamente exibido, inclusive `TODOS`, e codifica nomes com `&` e `/`.
4. Obra separada, inclusive crédito de obra: excluí-la da comparação e participação; manter a categoria na lista e explicar o valor separado com seu sinal.
5. Primeiro uso versus recorte sem gastos: distinguir ausência global de faturas de filtro vazio e de gastos que se anulam; oferecer importação ou troca de recorte conforme o caso.

**Decisões de apresentação:** maior valor primeiro; empates seguem a ordem de `CATS`. Todas as 13 linhas permanecem visíveis, inclusive obra separada (valor zero dentro do recorte, com indicação “fora deste recorte”). No filtro `TODOS`, mostrar soma do período e “sem comparação”, como no painel; não comparar um acumulado com uma média mensal. Com um mês anterior, usar `vs <rotuloMes>`; com dois ou três, `média de N meses`. Sem base, “sem comparação”; média ≤ 0 não produz porcentagem de variação. São decisões para completar a tela prevista na spec, sem mudar as contas do legado.

**Obra e destino:** `obra=1` exclui obra dos cálculos, mas hoje Lançamentos não a exclui da lista (`TelaLancamentos`/`listarTxn` só aplicam mês, cartões e categoria). O link mantém `obra=1` para a navegação; clicar em Construção / Obras abre seus lançamentos reais. Nessa linha, substituir selo, participação e variação por “fora deste recorte · abrir lançamentos”; usar pílula neutra. Não apresentar “na média” para uma categoria deliberadamente excluída. Essa exceção é apresentação, sem alterar `severidade`.

**Mês resolvido:** preservar `mesAtual`: mês ausente no cartão selecionado recua ao mais recente desse cartão. O subtítulo e os links usam esse mês; não prometer um vazio para mês inexistente. O seletor global ainda usa meses de todos os cartões, uma limitação herdada da 3.1 que esta entrega deve registrar na conferência visual.

checar('categorias ordena valor decrescente e empates em CATS',
