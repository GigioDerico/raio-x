# Fatia 3.1b — painel com o visual do app antigo — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O painel fica igual ao do app antigo — hero escuro com o total, variação, % da renda, total por cartão e a barra "já contratado × escolha"; três indicadores (juros, fixo todo mês, parcelas a vencer); ranking "Onde está apertando" com selo de severidade — portando marcação, CSS e as contas que faltam.

**Por quê:** o dono comparou o painel da 3.1 com o original (captura de 30/09) e decidiu **portar o visual**, pela mesma regra da lógica: porta, não reinventa. Isso derruba duas regras que o guia e o design system tinham escrito sem base no original ("verde como único acento", "vermelho só para erro") — o app antigo usa vermelho em juros e "acima da média", azul nas barras.

**Architecture:** As contas que o visual precisa e ainda não estavam portadas (`cartoesInfo`, `encargosDoMes`, `baseCategoria`, `severidade`, `parcelasInfo`) entram em `src/lib/calculos/` com paridade, como as outras. `resumoDoPainel` passa a devolver exatamente o que `renderKpis` e `renderRank` (docs/legado/app-antigo.html:1289–1351 e 1783–1806) calculam. A página porta a marcação desses dois `render*` para JSX e o CSS do legado para `globals.css`.

**Referências no legado (leia antes de cada task):**
- tokens: `docs/legado/app-antigo.html:7–45`
- CSS de cartão, hero, KPI, chip, ranking: `:90–135` e o bloco "redesign" `:561–630`
- `renderKpis`: `:1289–1351` · `renderRank`: `:1783–1806` · `encargosDoMes`: `:1114–1117`
- contas: `docs/legado/calculos-do-app-antigo.js` — `cartoesInfo` `:96–113`, `baseCategoria` `:159–165`, `severidade` `:211–218`, `parcelasInfo` `:267–296`

**Remanejo das subfatias:** com `baseCategoria`, `severidade` e `parcelasInfo` portadas aqui, a 3.2 fica só com a **tela Categorias** e a 3.3 só com a **tela Parcelas** (+ projeção). Atualizar a spec (§9) e `docs/acompanhamento/fatia-3.md` na Task 5.

**Fora:** o "Resumo de set/26" escrito pela IA (fatia 7); os tooltips `data-tip` (só hover — não existem no celular); as abas internas do app antigo (a casca da 3.0 já faz a navegação).

### Task 3: `resumoDoPainel` com o que o painel antigo mostra

**Files:** `src/lib/calculos/painel.ts`, `src/lib/calculos/adaptador.ts` + `src/lib/painel-repo.ts` (vencimento e renda), `scripts/testes.ts`.

- [ ] `LinhaPainel` ganha `vencimento: string | null` (de `statement.vencimento`, `to_char(…, 'YYYY-MM-DD')`), e `montarFaturas` o põe na fatura (`vencimento: l.vencimento ?? undefined`, só se ainda não houver). `carregarContexto` também lê `user_setting.renda_declarada` (posse por `user_id`) e devolve `renda: number` (0 se nulo).
- [ ] `resumoDoPainel(ctx, obraPorMes, separar, renda)` devolve, **com as mesmas contas de `renderKpis` e `renderRank`**:

```ts
export type LinhaRank = { cat: string; valor: number; share: number; sev: Severidade; varTxt: string };

export type ResumoPainel = {
  mes: string | null;
  meses: string[];
  vazio: boolean;
  obra: number | null;
  hero: {
    cur: number;
    prevMes: string | null;
    prev: number;
    delta: number | null;        // prev ? cur/prev - 1 : null  (igual ao legado)
    venc: string;                // vencimento mais cedo das faturas do mês, ou ''
    pctRenda: number | null;     // renda > 0 && mes ? cur / renda * 100 : null
    cartoes: { nome: string; cartao: string; total: number }[]; // cs.slice(0, 4)
    comp: Composicao;
    pcComp: number;              // comp.tot ? comprometido / tot * 100 : 0
    mesesCarregados: number;
  };
  stats: {
    encargos: number;            // encargosDoMes(m)
    fixoMensal: number;          // soma de recorrentesFixas().medio
    fixas: number;
    parcelasTotal: number;       // parcelasInfo().total
    proxParcela: { mes: string; tot: number } | null; // pi.porMes[0]
    comprasParceladas: number;
  };
  rank: LinhaRank[];             // renderRank: |v| > 0.009, desc; share = v/tot; sev e varTxt como lá
};
```

  `varTxt` e o texto do selo seguem `renderRank` exatamente (`pct(v/b.media - 1) + " · " + ref`, com `ref` = "média de N meses" ou "vs <mês>"; "sem comparação" quando não há base). O `vazio` continua o da 3.1 (com a obra à parte).
- [ ] Reescrever os testes de `resumoDoPainel` da 3.1 para o formato novo, mantendo a intenção de cada um (mês mais recente, total = porMes, comparação, ordem do ranking, obra à parte, todos os meses, vazio) e acrescentar: `delta` nulo quando `prev` é 0; `pctRenda` nulo sem renda; `cartoes` no máximo 4; `rank` inclui categoria com total negativo (o legado inclui — `|v| > 0.009`).
- [ ] `/api/overview` passa `renda`. `npm run typecheck && npm test`; commit "Painel: resumo com hero, indicadores e ranking do app antigo".
